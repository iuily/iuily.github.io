01

日常更新，按这四步走

  1. 打开内容编辑。“资料”可修改简介、英文名、兴趣、常用工具和社交链接；“作品”可填写项目状态与参与方式；“文章”点击“新增”即可开始记录。兴趣和工具用逗号分隔。
  2. 填写后点保存草稿，再点预览草稿。检查文字、封面和项目详情，满意后回到编辑页。
  3. 点下载 content.js。这一个文件包含全部资料、作品和文章；建议保留一份作为备份。
  4. 打开你的 GitHub 仓库，选择 Add file → Upload files，上传并替换根目录的同名 content.js，填写更新说明并提交到 main。若创建了新分支，再将更改合并至 main。等待 Pages 部署完成后刷新网站。
草稿和公开网站是两回事。
草稿只保存在当前浏览器；换设备、换浏览器或清理浏览数据后不会自动保留。只有上传并提交内容文件，访客才会看到更新。编辑页没有登录，也没有一键在线发布功能。若提示检测到旧版本草稿，可先下载备份，再点“恢复网站原有内容”载入当前资料。
GitHub 官方：添加文件到仓库 ↗
02

有真实截图时，再补充图片

目前项目没有提供截图，封面图片留空，网站会使用项目文字排版封面。以后可将截图放入网站的 assets 文件夹，并上传到仓库中相同的文件夹，在“封面图片”填写 ./assets/my-work.jpg。文件名和大小写必须一致，建议用中文、字母、数字、短横线或下划线。

在线预览前，图片需要已上传到网站。也可填写可访问的完整图片网址。文章正文按空行分段；要加小标题，可单独写一行 # 小标题，上下留空行。

03

第一次发布到 GitHub Pages

  1. 创建网站仓库。GitHub Free 账户需要使用公开仓库；网页和仓库内的网站文件会公开。
  2. 把交付文件夹 dist 内的全部文件和 assets 文件夹上传到仓库根目录。index.html 应直接出现在根目录，不要再套一层 dist。
  3. 进入仓库 Settings → Pages。在 Source 选择 Deploy from a branch，分支选 main，文件夹选 /(root)，点击 Save。
  4. 等待部署成功。Pages 设置页会显示网站地址，打开后检查首页和图片。后续提交到该分支即可触发更新。
GitHub 官方：配置 Pages 发布源 ↗
04

以后还能继续生长

需要换设备继续编辑时，在编辑页导入之前下载的 content.js 即可。若以后希望登录后上传图片、在线保存并直接发布，可以另行接入内容管理系统（CMS）；当前版本尚未提供这项服务。
